# Job submission validation matrix

This document complements [schema.json](schema.json). Implementations SHOULD apply these cross-field rules in **gateway** (return `400` with a clear error) and **orchestrator** (reject to DLQ / dead-letter stream with reason if a message slips through).

## Job and submission identifiers

| Field | Rule |
|--------|------|
| `job_id` | **Required.** Generated by **gateway** when the job resource is created (typically a new UUID per logical job). Exposed to clients and stored in metadata; orchestrator SHOULD set label **`hammrly.io/job-id`**. |
| `submission_id` | **Required.** Idempotency key for the **queue** message; stable when the client or gateway retries the same submission. MAY equal `job_id` if the gateway uses one UUID for both, or differ if the gateway uses separate ids for API resource vs queue deduplication. |

## User identity (`user_id`)

| Rule | Detail |
|------|--------|
| Purpose | Stable **end-user** identity for storage, audit, and **Kubernetes Job** labeling. |
| Source | **Gateway** MUST set `user_id` from authenticated context (e.g. internal user id, or OIDC `sub`). |
| Job label | **Orchestrator** SHOULD set `hammrly.io/user-id=<normalized>` on created Jobs (and related objects if consistent with policy). |
| Label value constraints | Kubernetes label **values** max **63** characters and must match `(([A-Za-z0-9][-A-Za-z0-9_.]*)?[A-Za-z0-9])?` (empty allowed, but user id should be non-empty in practice). If `user_id` exceeds length or charset rules, orchestrator MUST derive a deterministic label-safe value (e.g. **SHA-256 hex prefix** or a registered id mapping) — never drop attribution entirely. |

## Kueue LocalQueue (`kueue.x-k8s.io/queue-name`)

The **orchestrator** sets label `kueue.x-k8s.io/queue-name` on each Job. The LocalQueue name is **not** part of the job-submission JSON contract. Resolution order:

1. Per-kind env override on the orchestrator: **`HAMMRLY_KUEUE_QUEUE_DESKTOP`**, **`HAMMRLY_KUEUE_QUEUE_NOTEBOOK`**, **`HAMMRLY_KUEUE_QUEUE_CARTA`**, **`HAMMRLY_KUEUE_QUEUE_CONTRIBUTED`**, **`HAMMRLY_KUEUE_QUEUE_HEADLESS`** (non-empty value wins for that `workload.kind`).
2. Otherwise **`HAMMRLY_KUEUE_LOCAL_QUEUE_DEFAULT`** (e.g. `default`).

## Workload kind reference

| `workload.kind` | Meaning |
|-----------------|--------|
| `desktop` | Interactive desktop (NoVNC). |
| `notebook` | Interactive Jupyter Notebook. |
| `carta` | Interactive CARTA session. |
| `contributed` | Interactive session from a user-supplied `workload.image`. |
| `headless` | Non-interactive batch Job; many may be submitted. |

## Networking flags vs kind

`needs_service` and `needs_ingress` are **optional in the job JSON** (not required by [schema.json](schema.json)). The **gateway MUST normalize** missing values using the **deduction table** below **before** idempotency hashing and before publishing the envelope so the queue always carries explicit booleans.

| `kind` | Default `needs_service` | Default `needs_ingress` | Notes |
|--------|----------------------|-------------------------|--------|
| `desktop` | `true` | `true` | Browser access to NoVNC; gateway sets these when omitted. |
| `notebook` | `true` | `true` | Same for Jupyter HTTP. |
| `carta` | `true` | `true` | Interactive CARTA UI. |
| `contributed` | `true` | `true` | Interactive user image; if the client **explicitly** sets both to `false`, gateway MAY allow it only for documented product exceptions (e.g. port-forward-only access). |
| `headless` | `false` | `false` | Batch; no Service/Ingress by default when omitted. |

**Rules**

1. **Ingress implies Service**: after normalization, if `needs_ingress` is `true`, `needs_service` MUST be `true`. Gateway MUST reject (`400`) if a client sets `needs_ingress: true` with `needs_service: false` (before or after applying defaults). The orchestrator MUST reject the same if a malformed envelope appears.
2. **Interactive kinds** (`desktop`, `notebook`, `carta`): gateway MUST NOT allow `needs_service: false` or `needs_ingress: false` after normalization unless a future documented “edge proxy” or platform exception applies (currently disallow explicit `false` for these kinds).
3. **Explicit overrides**: if the client sends explicit booleans, gateway MUST validate they are **compatible with kind** per the rules above (stricter than silently accepting contradictory values).
4. **Headless**: if the client sets either flag to `true`, gateway MAY allow it; orchestrator MAY create those resources and SHOULD log unusual headless networking.

## `kind_options` vs kind

| `kind` | `kind_options` | Required inner key | Notes |
|--------|----------------|-------------------|--------|
| `desktop` | Optional | — | If present, only `novnc` allowed (see schema). |
| `notebook` | Optional | — | If present, only `jupyter` allowed; prefer `jupyter.token_ref` (SecretKeyRef) over embedding secrets in the queue. |
| `carta` | Optional | — | If present, only `carta` allowed. |
| `contributed` | Optional | — | If present, only `contributed` allowed (`command`, `args`, `working_dir`). |
| `headless` | **Required** | `batch` | `kind_options.batch` MUST be present (JSON Schema enforces). |

## Container probes (`kind_options.probes`)

Interactive workloads with **`needs_ingress=true`** use Kubernetes **readiness** (and optional **liveness** / **startup**) probes on the main workload container so the platform can detect when the session URL is safe to open.

Probes are declared in the job envelope under **`workload.kind_options.probes`**. The orchestrator renders them to Kubernetes `V1Probe` objects and resolves placeholders at pod build time.

### Placeholders

| Placeholder | Resolved to |
|-------------|-------------|
| `{ingress_path}` | Ingress path prefix for this submission (from orchestrator path templates), without trailing slash normalization surprises — use explicit paths in custom probes when unsure. |
| `{workload_port}` | Same integer as the workload Service `targetPort` (kind default or `kind_options.*.port`). |
| `"workload"` (probe `port` field) | Literal string meaning the workload container port (same as `{workload_port}`). |

### Requirements by kind

| `kind` | `kind_options.probes` | Notes |
|--------|------------------------|--------|
| `desktop` | Optional | Platform default: `httpGet` `{ingress_path}/` on workload port plus a **startup** probe with the same path (~5 min tolerance) when omitted. |
| `notebook` | Optional | Platform default: `httpGet` `{ingress_path}/api` on workload port when omitted. |
| `carta` | Optional | Platform default: `httpGet` `/` on workload port when omitted. |
| `contributed` | **`readiness` required** when `needs_ingress=true` | No safe default for arbitrary images. |
| `headless` | Ignored | Batch jobs do not use the session readiness / `access_url` flow. |

Gateway MUST reject (`400`) **`contributed`** workloads with `needs_ingress=true` and no `kind_options.probes.readiness`.

### Example (notebook)

```json
"kind_options": {
  "jupyter": { "port": 8888 },
  "probes": {
    "readiness": {
      "httpGet": { "path": "{ingress_path}/api", "port": "workload" },
      "initialDelaySeconds": 5
    }
  }
}
```

### Example (contributed)

```json
"kind_options": {
  "contributed": { "command": ["python", "-m", "http.server"] },
  "probes": {
    "readiness": {
      "httpGet": { "path": "/", "port": "workload" }
    }
  }
}
```

### Session readiness (`status=ready`)

After a readiness probe succeeds, the orchestrator sets submission **`status=ready`** and emits a **`session_ready`** event. Clients SHOULD poll `GET /v1/jobs/{job_id}` until `status == "ready"`, then open `access_url`. The earlier **`access_url_set`** event (and optional gateway tentative URL) is provisional.

## Desktop sessions (`workload.kind=desktop`)

Interactive desktops use the same submit path as notebooks (`POST /v2/session`). The client supplies **`workload.image`** (OCI reference) — for example `desktop-base`, `desktop-astronomy`, or `desktop-astronomy-gpu` images when published. Hammrly does not resolve or validate image names beyond schema rules.

### Caller resource sizing

Resources are **submit-time and fixed** for the pod lifetime. Each quantity is applied as both Kubernetes **request** and **limit** so Kueue admission matches actual cgroup ceilings. Size for peak usage (browsers, CASA, TOPCAT, etc.), not burstable headroom.

Example envelope:

```json
{
  "kind": "desktop",
  "name": "my-desktop",
  "image": "registry.example/hammrly/desktop-astronomy:1.0",
  "gpu_count": 0,
  "resources": {
    "cpu": "4",
    "memory": "8Gi",
    "ephemeral_storage": "20"
  },
  "kind_options": {
    "novnc": {"port": 6080}
  }
}
```

For **`desktop-astronomy-gpu`**, set **`workload.gpu_count`** (or `resources["nvidia.com/gpu"]`); orchestrator applies existing GPU node affinity and device requests.

### Platform-only `/dev/shm` (not in submit JSON)

The orchestrator mounts an in-memory `emptyDir` at **`/dev/shm`** on every desktop pod so GUI apps are not limited by Kubernetes’ tiny default shared-memory mount. Size is controlled by deployer config **`HAMMRLY_K8S_DESKTOP_SHM_DEFAULT`** (default `1Gi`), not by the submission envelope.

### Desktop image runtime contract

Reference desktop images SHOULD:

- Listen on **`kind_options.novnc.port`** (default **6080**)
- Honor **`NOVNC_PATH_PREFIX`** for ingress subpath serving
- Run as non-root UID/GID matching **`HAMMRLY_K8S_JOB_RUN_AS_USER`** / **`HAMMRLY_K8S_JOB_RUN_AS_GROUP`** (default **1000**)
- Respond to the platform default readiness probe at **`{ingress_path}/`** on the NoVNC port (or supply custom `kind_options.probes`)

## GPU count (`workload.gpu_count`) vs `nvidia.com/gpu` resources

| Rule | Detail |
|------|--------|
| Primary field | **`workload.gpu_count`** (non-negative integer) is the preferred way to request NVIDIA GPUs. |
| Legacy | **`resources["nvidia.com/gpu"]`** quantity string may still be used; orchestrator derives the count when `gpu_count` is omitted. |
| Consistency | Gateway SHOULD keep `gpu_count` and `nvidia.com/gpu` aligned if both are set; orchestrator treats **`gpu_count` as authoritative** when present and overwrites/aligns device requests accordingly. |
| Scheduling | Orchestrator pins **GPU workloads** to nodes labelled **`skaha.opencadc.org/node-type=gpu-worker-node`** (override via `HAMMRLY_K8S_GPU_NODE_LABEL_*`) and **excludes** those nodes when no GPUs are requested. |

## Headless / batch semantics

| Rule | Detail |
|------|--------|
| Entrypoint | Either the container `image` ENTRYPOINT is used or `kind_options.batch.command` / `args` override it; at least one path MUST yield a runnable container (implementations SHOULD validate when `command` and `args` are both empty against images known to have no entrypoint). |
| `parallelism` | If omitted, orchestrator uses Job default (`1`). |
| `backoff_limit` | If omitted, orchestrator uses platform default or Kubernetes default. |

## Workspace data flow

Every orchestrated Job mounts a per-pod `emptyDir` at `/workspace` and shares it across three phases:

1. An `input-downloader` init container creates `/workspace/inputs` and `/workspace/outputs`, then downloads optional `workload.input_uri` into `/workspace/inputs`.
2. The main `workload` container runs the user image and writes processing products under `/workspace/outputs`.
3. An `output-watcher` sidecar waits for `/workspace/hammrly-complete.json` or `/workspace/hammrly-error.json`. Error JSON makes the sidecar exit nonzero. Completion JSON follows the [workload completion contract](../../workload-completion/v1/schema.json), and its `outputs` entries choose which files are uploaded. When an output entry omits `destination_uri`, `workload.output_uri` is used as the destination prefix.

The default helper image currently supports `http`, `https`, `file`, and local-path inputs, and `http`/`https` PUT or file/local-path output destinations. Use pre-signed URLs for object stores unless the deployment provides a custom helper image.

## Resources

| Rule | Detail |
|------|--------|
| Non-empty | Gateway SHOULD require at least `cpu` or `memory` (or gpu) so workloads are schedulable predictably; JSON Schema allows an empty `resources` object for forward compatibility — enable stricter validation in code. |
| Ephemeral storage unit | Callers set `resources.ephemeral_storage` in GB (Gigabytes). Gateway and orchestrator normalize accepted values to Kubernetes decimal `G` quantities. |
| Ephemeral storage default | Gateway and orchestrator SHOULD ensure `resources.ephemeral_storage` is present. The platform default is 20GB when callers omit it. |
| Ephemeral storage maximum | Gateway SHOULD reject `resources.ephemeral_storage` GB values above the deployer-configured maximum. Orchestrator MUST enforce the same cap before creating a Kubernetes Job. |
| Quantities | Each resource value is a single Kubernetes quantity string; orchestrator sets matching request and limit. Platform policy MAY cap values and reject disallowed extended resource keys. |

## Logical name

| Rule | Detail |
|------|--------|
| `workload.name` | Human-entered or API-provided logical name; MUST be sanitizable to RFC 1123 labels. Orchestrator SHOULD derive unique Kubernetes `metadata.name` using `submission_id` (e.g. prefix or hash) to avoid collisions. |
